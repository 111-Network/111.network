## 2. Judge panel

Four lenses, read-only, over the built HTML and `src/`: layer logic vs `os/README.md`, tech leaks (W1/W2/W4/W5), design
system (`DESIGN.md`), accessibility and performance in a browser at 375 px and 1280 px. Every finding then went to two
independent refuters; a finding survived only if both kept it.

**23 findings raised, 4 survived, all 4 fixed:**

| Lens | Finding | Fix |
|---|---|---|
| logic | The Local AI agent "cannot touch hardware or run commands" contradicted the README's agent, which tests fixes in a sandbox, and the site's own Repairs page | "It cannot touch hardware or change this node by itself: a fix runs only in its sandbox until you accept it." (`copy/core.ts`, `copy/services.ts`) |
| design | The floating cookie banner used `backdrop-blur-md`; `DESIGN.md` §10 allows blur on the nav only | solid `bg-background` (`cookie-banner.tsx`) |
| a11y | The "change" link under the following line (Layers 3, 8, 9) was a 39 × 13 px target at 375 px; plan §7 asks for 44 px targets | 44 px tall inline-flex hit area, same 10 px line (`common/following-device.tsx`) |
| a11y | The Overview "open" links in the needs-you rows were 29 × 16 px targets | 44 px hit area through a pseudo-element, text-sized paint (`demo/views/overview/index.tsx`) |

**19 refuted** (kept as decided; the reasons, in short): L1 "Install & updates" story, L4 "every node serves its own
dashboard", L6 "runs on bridge boxes and hubs", the laptop bridge rule, L3 offload never over long-range radio, L0
concepts carry no grade: all verbatim owner decisions in the plan (§5, §6.4, §6.8). L5 "no length limit" and the
queued-reason sentences: verbatim from the README's "limits come from physics" rule and from the real dashboard
strings. "Standard tier (local model)", the `gpu-pc` note id, the unreachable "coming soon" terminal branch: not
category codes or visible marks under W4/W5 as written. Destructive red on the update step marker: `destructive` is
not a status-dot token. Inline "Terms" and `change` links under 44 px, `text-[9px]` packet labels, Silkscreen on
`/terms`, the lucide icon the cookie banner shows on `/demo`, `aria-modal` missing on the Radix home sheet, the
analytics 404 on a local `next start`: measured correctly, but outside the plan's rules or decided elsewhere (the
`change` link was fixed anyway, see above).

Two more observations from the `/demo` spec author, decided rather than changed:
- A service deep link switches the view to ADVANCED for that visit and does **not** save it; only the SIMPLE | ADVANCED
  control saves. The spec pins this.
- Ada's reply stays on its 2.6 s timer under reduced motion (a message from someone else is not an animation);
  `slices/messages.test.ts` already states it.
- One real copy slip was fixed: the rejected-fix line on Repairs now names the service like the reason beside it
  ("The message store stays broken"), not the layer word.

## 3. Lighthouse mobile (idle machine, production build, `--preset=perf --form-factor=mobile`)

| Page | Perf | A11y | Best practices | SEO | FCP | LCP | TBT | CLS |
|---|---|---|---|---|---|---|---|---|
| `/` | 77 | 97 | 96 | 100 | 1.9 s | 4.0 s | 390 ms | 0 |
| `/demo` | 81 | 100 | 96 | 100 | 1.6 s | 4.5 s | 170 ms | 0.058 |

The throttled-mobile LCP (about 4 s on both pages) is the one number worth a follow-up: both pages paint the pixel
display font and a 240 kB first-load bundle before the largest element settles. It is outside this phase's fix round
(the first-load budgets in `pnpm budget` hold with 33 kB headroom); a later task can look at the font loading and the
hero's first paint.

Of the audits under 0.9:
- **color-contrast (home):** the ghost layer numbers (`0N`, 8 % foreground, `aria-hidden`) and the Layer 7 inverted
  header's ghost number. Decorative by design (`DESIGN.md` "Ghost Number Header"), hidden from assistive technology;
  accepted. The one real miss, the Layer 5 on/off tag at 70 % opacity (4.17:1), is fixed.
- **label-content-name-mismatch (home):** before the fix round, the Layer 6 network toggles and bridge bands and the
  Layer 7 node markers had aria-labels that did not start with their visible words. Fixed and gone from the final run:
  names come from the visible text, with an sr-only tail where the old label said more.
- **errors-in-console:** the analytics script 404s on a local `next start` (it is served by the production host only).
- **render-blocking CSS, legacy JS, unused JS:** the framework's one stylesheet and its polyfills; no action in this phase.
- **dom-size (home, ~2.4k elements):** the Layer 8 store map grid and the ten interactive sections on one page; within
  the motion and first-load budgets (`pnpm budget`), no action.

## 4. What this phase does not cover

- A real end-to-end test with a Meshtastic radio (or the Meshtasticator simulator) is an **owner bench gate in the os
  repo** (`6-transport/TASKS.md` "External gates", `7-relay/TASKS.md`), not something a website test can run. The os
  repo's Meshtastic paths are verified against fakes in `cargo test` only. Nothing in this repo claims otherwise:
  Meshtastic is named once, in the Layer 6 line (W2), never in `/demo`.
- The e2e suite is not part of `pnpm check` and there is no CI workflow in this repo (plan: Vercel builds run
  `pnpm build`, which includes `check-copy`). Running `pnpm e2e` before a release is a manual step.
